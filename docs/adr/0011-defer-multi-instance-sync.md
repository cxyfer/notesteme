# ADR-0011：多實例同步延到 Hub 階段

- 狀態：已採納
- 日期：2026-11-11
- 修訂：2026-11-12，釐清選配 Postgres backend 和多實例同步的差別

## 背景

- WSL Docker 和 VPS 可能各跑一個實例。
- 兩個實例同時運作時，可能出現：
  - 同一部影片處理兩次，重複付費轉錄。
  - 同時寫入同一個 vault，產生 git 衝突。
- 要真正解決這個問題，需要同步狀態，這個成本很高。

## 決策

1. 在 Hub 出現之前，各實例獨立運作，**不做自動同步**。
2. 現在先做幾件低成本的準備，讓之後的同步不用改架構：
   - 所有記錄都用全域唯一 ID（UUIDv7），合併時不會撞號。
   - 每個實例都有 `instance_id`，寫進每筆影音與產出。
   - 產出都有內容 hash（`sha256`），可以去重。
   - Bundle 匯出與匯入（ADR-0005）作為手動同步的方式。
3. 暫時的使用規則：
   - 同一個頻道只在一個實例上訂閱。
   - `git` adapter 遇到衝突時回報，不自動處理。
4. Hub 階段再評估：
   - 由 Hub 協調「哪部影片正在由哪個實例處理」。
   - 實例之間透過 Hub 交換 bundle。

## 考慮過的選項

- **現在就做雙向同步**（例如 CRDT 或 event log 複製）：太複雜，目前沒有足夠的需求。
- **共用一個遠端資料庫**：等於放棄單機獨立運作的設計，也會讓 SQLite 的選擇失去意義。
  - ADR-0007 的選配 Postgres＋Redis backend 是讓**同一個實例**的多個 worker 共用佇列，仍然是一個實例、一份資料，不屬於這裡說的多實例同步。

## 影響

- 好處：
  - Client 維持簡單。
  - 之後的同步不必遷移資料。
- 代價：
  - 使用者要自己避免兩個實例訂閱同一個頻道。
  - UI 在新增訂閱時，可以提醒使用者這一點。
