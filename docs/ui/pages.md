# Episteme 頁面規格

> 狀態：草案 v0.1（2026-11-11）
> 設計語言見 [design-language.md](design-language.md)，共用模式與文案見 [README.md](README.md)。
> 線框圖只表示資訊的位置與層級，不代表實際比例。圖中符號的意思：`█` 完成、`▒` 處理中（顯影動畫）、`┄` 未開始、`✕` 失敗、`▼` 選中的畫面、`┃` 播放頭。

## 1. 總覽

- **目的**：打開 App 時一眼看到三件事：現在在處理什麼、有什麼需要我處理、今天發生了什麼。
- **里程碑**：M4。M1–M3 期間，`/` 先導到媒體庫。

```
總覽

現在                                                              處理中 3 部
为什么AI时代，越来越多公司选择 PostgreSQL       ▁▂▅▇▆▃▁▃▆▇▅▂▁▂▄▆▇▅▃▂▁
                                                ████████████████████████  字幕
                                                ██████████▒▒▒┄┄┄┄┄┄┄┄┄┄┄  校正 9/16
AI Agent面試到底考什麼？我的真實復盤            ▃▅▆▅▃▂▅▆▇▆▅▃▂▃▅▆▅▃▂▁▂▃
                                                ███████▒▒┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  轉錄 3/5 段

需要你處理                                                             2 項
YouTube cookie 已失效，3 部影片無法下載。                 [ 上傳新的 cookie ]
「为什么AI时代…」第 10 段的校正連續 3 次驗證失敗。   [ 查看 ]  [ 改用 API 處理 ]

今天
14:02  PostgreSQL in 100 Seconds 的筆記已寫入 vault
13:40  码农高天 有 1 部新影片
09:15  佇列處理完 6 個任務，花費 $0.38

本月花費 $3.42，預算 $20                                         [ 查看成本 ]
```

- **元件**：
  - 「現在」最多列 3 部，用精簡版時間帶；超過 3 部時顯示「還有 N 部」，連到佇列。
  - 「需要你處理」的每一項都有直接處理的按鈕。沒有項目時，整個區塊隱藏。
  - 「今天」是依時間排列的事件。
- **互動**：點時間帶會打開影音詳情頁，並定位到那個時間。
- **狀態**：完全沒有資料時，顯示媒體庫的空狀態。
- **API**：`GET /api/overview`、`GET /api/events`（SSE）

## 2. 新增

- **目的**：把網址或檔案交給 Episteme 處理。這是最常用的動作。
- **里程碑**：M1
- **開啟方式**：
  - 導覽列的「新增」按鈕。
  - `N` 快捷鍵。
  - 指令面板。
  - 焦點不在輸入框時貼上網址。
  - 把檔案拖進視窗。

```
新增                                                                    ✕
┌ 貼上網址（一行一個），或拖放影片、音訊檔 ───────────────────────────┐
│ https://www.youtube.com/watch?v=…                                    │
│ https://www.bilibili.com/video/BV…                                   │
└──────────────────────────────────────────────────────────────────────┘
辨識到 YouTube 影片 1 部、Bilibili 影片 1 部（共 3 個分P）
  Bilibili 分P：  (●) 全部   ( ) 只要 P1   ( ) 自己選

處理方案   標準筆記 ▾
調整這次的設定 ▾
  目標語言   zh-Hant-TW ▾
  字幕來源   人工字幕 › 自動字幕 › Supadata › whisper-1        [ 調整順序 ]
  步驟       [✓] 校正   [✓] 翻譯   [✓] 關鍵畫面   [✓] 筆記

預估花費約 $0.21。兩部都有自動字幕，所以可能用不到 whisper-1。

                                                              [ 開始處理 ]
```

- **元件**：
  - 網址輸入框：即時辨識平台與類型（影片、播放清單、頻道、Podcast RSS）。
  - 貼上頻道或 RSS 網址時，改為提示「要訂閱這個頻道嗎？」，並附上「建立訂閱」按鈕。
  - 「調整這次的設定」預設收合，只影響這一次，不會修改處理方案。
- **互動**：
  - 已經處理過的影音會標示「已在媒體庫中」，並提供「打開」或「重新處理」。
  - 按「開始處理」後關閉抽屜，toast 顯示「已開始處理 2 部」，並附上「查看」連結。
- **狀態**：
  - 辨識失敗：「無法辨識這個網址。目前支援 YouTube、Bilibili、Podcast RSS 與本機檔案。」
  - 需要 cookie 的內容：在送出前提示，並附上設定連結。
- **API**：`POST /api/resolve`（辨識網址）、`POST /api/estimate`、`POST /api/items`

## 3. 媒體庫

- **目的**：瀏覽、篩選、搜尋所有影音，並做批次操作。
- **里程碑**：M1 提供列表、基本篩選、標題搜尋；M4 加上字幕全文搜尋、儲存檢視、批次操作。

```
媒體庫
┌ 搜尋標題或字幕內容 ─────────────────────────────┐  頻道 ▾  平台 ▾  狀態 ▾  發布日 ▾  更多 ▾
└─────────────────────────────────────────────────┘
已套用：頻道是码农高天、校正未完成    [ 清除 ]  [ 存成檢視 ]      依發布日排序 ▾   列 ｜ 格

码农高天                                                                       12 部
───────────────────────────────────────────────────────────────────────────────────────
[縮圖]  为什么AI时代，越来越多公司选择 PostgreSQL    23:41   ▁▂▅▇▆▃▁▃▆▇▅▂▁▂▄▆▇▅▃▂▁
        2026-11-11 發布                                      ████████████████████████  字幕
                                                             ██████████▒▒▒┄┄┄┄┄┄┄┄┄┄┄  校正 9/16
[縮圖]  …
最佳拍檔                                                                        8 部
───────────────────────────────────────────────────────────────────────────────────────
[縮圖]  AI Agent面試到底考什麼？我的真實復盤          41:08   ▃▅▆▅▃▂▅▆▇▆▅▃▂▃▅▆▅▃▂▁▂▃
        2026-11-04 發布                                      ████████████████████████  字幕
                                                             ███████████████✕████████  校正，第 7 段失敗
```

- **元件**：
  - 預設依頻道分組，也可以改成依發布日或依狀態分組。
  - 每一列包含：縮圖、標題、發布日、長度，以及精簡版時間帶和步驟帶。
  - 「格」檢視是印樣式的縮圖網格，只在瀏覽畫面時使用，不是預設。
  - 篩選條件：
    - 頻道、平台、各步驟的狀態、錯誤類別、發布日、長度。
    - 語言、已讀狀態、有沒有筆記、時間來源（例如只看含推算時間的影音）。
  - 選取多列後，頂部出現批次操作列：重新處理（選擇從哪個步驟開始）、改用其他處理方案、匯出 bundle、刪除媒體檔、標為已讀。
- **字幕全文搜尋**（M4）：
  - 結果以「字幕句」為單位，顯示時間碼與前後文。
  - 點擊會打開影音詳情頁，並定位到那一句。
- **互動**：
  - 點擊列會打開影音詳情頁；點擊時間帶會定位到該時間。
  - 列表使用虛擬捲動，數千筆也保持流暢。
  - 新項目進來時只顯示「有 N 個新項目」的提示，不會打亂目前的列表。
- **狀態**：空狀態與篩選結果為空，文案見 [README §4.3](README.md#43-空狀態範例)。
- **API**：`GET /api/items`、`GET /api/search`、`POST /api/items/batch`、`GET/POST /api/views`

## 4. 影音詳情

- **目的**：檢視單一影音的字幕、畫面、筆記與處理紀錄，並從任一步驟重新處理。
- **里程碑**：M1 提供字幕分頁；M2 加上對照、差異與重新處理；M3 加上畫面與筆記分頁。

```
媒體庫 ›
为什么AI时代，越来越多公司选择 PostgreSQL
頻道 码农高天   平台 YouTube   發布 2026-11-11   長度 23:41   處理方案 標準筆記
                                                         [ 重新處理 ▾ ]   [ 匯出 ▾ ]
┌──────────────────────────────────────────────────────────────────────────────────┐
│ 0:00          5:00          10:00         15:00         20:00             23:41 │
│ ▁▂▅▇▆▃▁▃▆▇▅▂▁▂▄▆▇▅▃▂▁▂▅▇▆▃▁▃▆▇▅▂▁▂▄▆▇▅▃▂▁▂▅▇▆▃▁▃▆▇▅▂▁▂▄▆▇▅▃▂▁▂▅▇▆▃▁▃▆▇▅▂▁▃ │
│ │前言        │PostgreSQL 的擴充性      │向量搜尋           │取捨                │
│     ▼     ▼         ▼    ▼          ▼         ▼           ▼                     │
│ ████████████████████████████████████████████████████████████████████████  字幕   │
│ ██████████████████████████████▒▒▒▒┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  校正   │
│                  ┃                                                              │
└──────────────────────────────────────────────────────────────────────────────────┘
┌─────────── 播放器 ───────────┐   字幕   畫面   筆記   紀錄
│                              │   原始 ｜ 校正 ｜ 譯文 ｜ 對照 ｜ 差異        譯文語言 zh-Hant-TW ▾
│                              │   ───────────────────────────────────────────────────
│                              │     04:12   我們先看一下為什麼 Postgres 的擴充性
└──────────────────────────────┘   ▌ 04:16   這麼好，關鍵在於它的 extension 機制
章節                                 04:21 ◦ 你可以把它想成一個外掛系統
  前言                    0:00
  PostgreSQL 的擴充性     3:58
  向量搜尋               10:12
  取捨                   17:30
```

- **頂部完整版時間帶**：同時當作播放器的拖曳軸。拖曳可以選取範圍，選取後出現「重新校正這段」「複製這段字幕」。
- **播放器**：
  - YouTube 用 IFrame Player API。
  - Bilibili 用官方嵌入播放器，網址帶 `bvid`、`p`、`t`；能否控制播放位置要在 M0 實測，不行時改成「在 Bilibili 開啟這個時間」。
  - 本機檔案與 Podcast 用 HTML5 media，由後端提供並支援 Range 請求。
- **分頁**：
  - **字幕**：使用字幕句列表元件（見設計語言 §6.2）。切換顯示模式不會改變捲動位置。
  - **畫面**（M3）：使用印樣元件。可以只看選中的畫面，也可以看全部候選；每張選中的畫面都顯示圖說與它所屬的章節。
  - **筆記**（M3）：
    - 用閱讀字體渲染 Obsidian 風格的 Markdown，支援 callout、wikilink、`![[…]]` 圖片嵌入。
    - 標題上的時間戳連結點擊後會讓播放器跳到那個時間。
    - 右側顯示自動檢查的結果，例如「所有章節都有時間戳」「引用的 12 張圖片都存在」。
    - 顯示寫入狀態：已寫入 vault、檔案路徑、git commit。
  - **紀錄**：
    - 依步驟列出狀態、開始與結束時間、耗時、花費、provider、model、prompt 版本、log。
    - 每個產出都有版本，可以比較兩個版本的差異。
- **重新處理**選單：
  - 從某個步驟開始重新處理。
  - 換 prompt 或模型重新生成，會產生新版本，舊版本保留。
  - 改用 API 處理（只在任務等待 Agent 時出現）。
- **匯出**選單：SRT、VTT、ASS（選擇樣式）、雙語 SRT、純文字、Markdown 筆記、bundle。
- **API**：
  - `GET /api/items/:id`
  - `GET /api/items/:id/cues?variant=&lang=&from=&to=`
  - `GET /api/items/:id/frames`
  - `GET /api/items/:id/note`
  - `GET /api/items/:id/runs`
  - `POST /api/items/:id/rerun`
  - `GET /api/artifacts/:id/content?format=`
  - `GET /api/items/:id/media`（Range）

## 5. 訂閱

- **目的**：管理追蹤的頻道與 Podcast，並在套用前預覽會抓到哪些內容。
- **里程碑**：M4

```

頻道                   平台       檢查頻率     上次檢查     下次檢查     處理方案      新內容
码农高天               YouTube    每 6 小時    13:40        19:40        標準筆記      1
最佳拍檔               YouTube    每 12 小時   09:02        21:02        只要字幕      0
原子能                 Bilibili   每天         08:00        明天 08:00   標準筆記      0
```

訂閱詳情或編輯（抽屜）：

```
码农高天                                                                    ✕
來源         https://www.youtube.com/@…
處理方案     標準筆記 ▾
檢查頻率     每 6 小時 ▾
回補範圍     (●) 只抓之後的新內容   ( ) 最近 10 部   ( ) 全部
過濾條件     長度 5 到 90 分鐘    [✓] 排除 Shorts    [✓] 直播等回放出來再處理
             標題不包含  /抽獎|直播預告/

試跑預覽（依目前的設定）
會處理 8 部
  2026-11-11   为什么AI时代，越来越多公司选择 PostgreSQL      23:41
  …
略過 4 部
  2026-11-09   一分钟看懂向量数据库 #shorts                   0:58      原因：Shorts
  2026-11-02   直播回放：…                                    2:10:00   原因：超過 90 分鐘

                                         [ 立即檢查 ]   [ 儲存變更 ]
```

- **互動**：
  - 修改過濾條件時，試跑預覽會即時更新。
  - 「立即檢查」會馬上執行一次探索，結果顯示在 toast 中。
  - 新增訂閱時提醒：「同一個頻道只在一台實例上訂閱，避免重複處理。」（見 ADR-0011）
- **API**：`GET/POST/PATCH /api/subscriptions`、`POST /api/subscriptions/:id/preview`、`POST /api/subscriptions/:id/check`

## 6. 佇列

- **目的**：看到每個資源類別的並行狀況，並調整上限、暫停、重試或取消任務。
- **里程碑**：M1

```
佇列                                         Agent 一次最多領取 4 個 ▾     [ 暫停佇列 ]

下載     ■ □               使用中 1，上限 2      等待 3
         └ PostgreSQL in 100 Seconds        影片 1080p     64%
轉錄     ■ ■ □             使用中 2，上限 3      等待 0
         ├ AI Agent面試到底考什麼？          whisper-1      第 3/5 段
         └ 为什么AI时代…                     Supadata       等待結果
LLM      ■ ■ ■ ■           使用中 4，上限 4      等待 12
         ├ 校正   为什么AI时代…    第 10/16 段   由 Claude Code 處理中，租約剩 7:42
         ├ 翻譯   PostgreSQL in…   第 2/4 段     API：anthropic
         └ …
畫面     □ □ □ □           閒置

失敗 2 項                                                              [ 全部重試 ]
  校正   AI Agent面試…   第 7 段    驗證失敗 3 次           [ 重試 ]  [ 改用 API 處理 ]
```

- **元件**：
  - 每個資源類別一條通道，方格的數量就是並行上限，實心方格是使用中。
  - 上限可以直接點擊調整（`+`／`−`），立即生效。
  - Agent 領取的任務會顯示是哪個 Agent，以及租約還剩多少時間。
  - 每個資源類別都可以單獨暫停。
- **互動**：點任務會打開影音詳情頁的「紀錄」分頁。
- **狀態**：空狀態見 README §4.3。佇列暫停時，頂部顯示「佇列已暫停，新任務不會開始。」並附上「繼續處理」按鈕。
- **API**：`GET /api/queue`、`PATCH /api/queue/limits`、`POST /api/queue/pause`、`POST /api/queue/resume`、`POST /api/tasks/:id/retry`、`POST /api/tasks/:id/cancel`、`POST /api/tasks/:id/switch-executor`

## 7. Prompt 庫

- **目的**：管理與調整各步驟的 prompt。因為校對只靠 LLM，這是改善結果最主要的地方。
- **里程碑**：M2

列表依用途分組：斷句、校正、翻譯、選圖、筆記。每個 prompt 顯示目前版本、被哪些處理方案使用、最後修改時間。

編輯頁：

```
Prompt 庫 › 校正 › correct-default
版本  v3（使用中）  v2  v1                       [ 比較版本 ]  [ 另存新版本 ]  [ 設為預設 ]
┌ 編輯器 ──────────────────────────────────┐ ┌ 試跑 ──────────────────────────────────┐
│ 你是字幕校對員。只修正錯字、專有名詞與   │ │ 影音   为什么AI时代…  ▾                │
│ 標點，不改變句意，也不合併或拆分句子。   │ │ 範圍   04:00 到 06:00                  │
│                                          │ │ 模型   anthropic ／ <model-id> ▾       │
│ 詞彙表：                                 │ │                                        │
│ {{glossary}}                             │ │ 預估 $0.004                [ 試跑 ]    │
│                                          │ │ ───────────────────────────────────── │
│ 可用變數：title、channel、description、  │ │ 04:16 這麼好，關鍵在於它的              │
│ chapters、glossary、source_lang、        │ │       ~~extention~~ extension 機制     │
│ target_lang                              │ │ 驗證通過：句數相同，最低相似度 0.91    │
└──────────────────────────────────────────┘ └────────────────────────────────────────┘
```

- **元件**：
  - 編輯器用 CodeMirror 6，變數會高亮，未定義的變數會標示錯誤。
  - 試跑結果用字幕句列表的「差異」模式顯示，並附上驗證結果。試跑不會寫入任何產出。
  - 「比較版本」並排顯示兩個版本的 prompt 差異，也可以用同一段字幕比較兩者的輸出。
- **互動**：「另存新版本」後，正在使用它的處理方案不會自動改用新版，要按「設為預設」或到處理方案中更新。
- **API**：`GET/POST /api/prompts`、`GET /api/prompts/:id/versions`、`POST /api/prompts/:id/versions`、`POST /api/prompts/playground`

## 8. 處理方案

- **目的**：組合一套可重複套用的 pipeline 設定。
- **里程碑**：M2

```
處理方案 › 標準筆記                                   [ 複製 ]   [ 儲存變更 ]
字幕 › 斷句 › 校正 › 翻譯 › 匯出 › 關鍵畫面 › 筆記 › 寫入 vault

1 字幕來源    順序  人工字幕 › 自動字幕 › Supadata › whisper-1    [ 調整 ]
              原文語言優先  original › zh-Hans      平台機器翻譯字幕  不使用
2 斷句        API 處理 ▾     openai ／ <model-id> ▾      prompt  segment-default v2 ▾
              段內切分的時間   需要時才切，先找停頓點 ▾
3 校正        交給 Agent ▾                                prompt  correct-default v3 ▾
4 翻譯        API 處理 ▾     anthropic ／ <model-id> ▾   目標語言  zh-Hant-TW、en
5 匯出        SRT、ASS（樣式 default）
6 關鍵畫面    每分鐘最多 1 張，整部最多 16 張，依片長的建議範圍 ✓
              選圖  API 處理 ▾  gemini ／ <model-id> ▾
7 筆記        模板  Video Notes 預設 ▾    API 處理 ▾
8 寫入 vault  git：private/master ▾
```

- 步驟本身有先後順序，所以這裡使用編號。
- 頂部的流程列會反映哪些步驟被啟用；設成「不執行」的步驟會變淡。
- 每個 LLM 步驟都可以選擇 API 處理、交給 Agent 或不執行。
- 被頻道訂閱使用的處理方案，在修改前會提示有哪些訂閱會受到影響。
- **API**：`GET/POST/PATCH /api/profiles`

## 9. 字幕樣式

- **目的**：選擇或自訂 ASS 樣式，並看到實際的渲染結果。
- **里程碑**：M2

```
字幕樣式 › default（內建）                                    [ 複製成自訂樣式 ]
┌ 預覽（用 libass 實際渲染）──────────────────────────┐ ┌ 原文行 ｜ 譯文行 ｜ 版面 ┐
│                                                     │ │ 字型    Noto Sans CJK TC ▾│
│                                                     │ │ 大小    52                │
│                                                     │ │ 文字    #FFFFFF           │
│           我們在這裡用 Kafka。                       │ │ 描邊    #000000   2.5     │
│           We use Kafka for this.                    │ │ 陰影    0                 │
└─────────────────────────────────────────────────────┘ │ 位置    底部置中 ▾        │
預覽畫面   为什么AI时代… 04:16 ▾      解析度 1920×1080   │ 邊距    垂直 48           │
                                                         └───────────────────────────┘
內建樣式   default   translation-top   translation-only   large   boxed   minimal
                                                                  [ 匯入 .ass 樣式 ]
```

- **元件**：
  - 預覽是後端用 ffmpeg + libass 把樣式渲染在指定畫面上，回傳圖片。調整欄位後延遲 300ms 再更新預覽，避免連續請求。
  - 內建樣式用同一張畫面渲染成縮圖並排比較。內建樣式不能修改，只能複製後再自訂。
  - 「版面」分頁設定原文與譯文誰在上方，或只顯示其中一種。
  - 字型依目標語言自動帶入預設值，例如 zh-Hans 帶入 Noto Sans CJK SC。
- **API**：`GET/POST/PATCH /api/ass-styles`、`POST /api/ass-styles/preview`（回傳 PNG）、`POST /api/ass-styles/import`

## 10. 筆記模板

- **目的**：定義筆記的結構（模板）與內文的寫法（prompt），並用真實的影音預覽結果。
- **里程碑**：M3
- **版面**：三欄。
  - 左：模板，包含 frontmatter、資訊表與章節骨架。模板的輸出是 Markdown，LLM 只負責填入內文。
  - 中：筆記 prompt。
  - 右：預覽。選擇一部已處理的影音，用閱讀字體渲染結果。
- **版面規則**：
  - 檔名、資料夾版面、附件位置寫成可調整的規則。
  - 預設是「Video Notes 預設」，依照 `Video Notes/AGENTS.md`：`Channel/` 用 `YYYY-MM-DD_<標題>.md`，其他資料夾用 `<標題> - YYYY-MM-DD.md`。
- **自動檢查**：
  - 可以勾選要檢查的項目，例如：必要的 frontmatter 欄位、每個內容標題都有時間戳、圖片都存在、有「自我檢驗」段落。
  - 檢查失敗時，任務會標示「需要你處理」，不會寫入 vault。
- **API**：`GET/POST/PATCH /api/note-templates`、`POST /api/note-templates/:id/preview`

## 11. 成本

- **目的**：看錢花在哪裡，並設定預算。
- **里程碑**：M4
- **版面**：
  - 頂部一行文字：「本月花費 $3.42，預算 $20，預計月底約 $9.80。」後面接「調整預算」。
  - 下方是依日期的長條圖，可以切換依 provider、頻道或步驟分組。
  - 最下方是明細表格：日期、影音、步驟、provider、model、用量（分鐘、token 或 credit）、金額。可以篩選與匯出 CSV。
- 不使用大數字統計卡。
- **API**：`GET /api/costs?group_by=&from=&to=`、`PATCH /api/settings/budget`

## 12. 設定

- **目的**：管理所有外部服務、帳號、輸出與系統狀態。
- **版面**：左側是分區清單，右側是表單，每個分區各自儲存。

| 分區 | 內容 | 里程碑 |
|---|---|---|
| 服務與金鑰 | ASR、LLM、Supadata 的 provider 與 API key；每個都有「測試連線」按鈕；顯示模型的停用公告 | M1 |
| 帳號與 Cookie | 上傳 YouTube、Bilibili cookie，加密存放；顯示最後一次成功使用的時間與是否失效 | M1 |
| 語言 | 預設目標語言、原文字幕的語言優先順序、介面語言 | M1 |
| 輸出 | Vault 寫入方式（本機資料夾或 git）、路徑或 repo、分支、使用者修改過時的處理方式、寫入後執行的命令 | M3 |
| MCP 與 Agent | 產生與撤銷 token；顯示 Claude Code 的設定片段；Agent 一次最多領取幾個、租約時長 | M2 |
| 通知 | ntfy、Discord、Telegram、webhook；分別勾選要通知哪些事件；「傳送測試通知」 | M4 |
| 預算 | 月預算、單部上限、預算將用完時的通知門檻 | M4 |
| 系統 | yt-dlp、ffmpeg、Deno 的版本；「更新 yt-dlp」與「回到上一個版本」；磁碟用量；媒體檔保留天數 | M1 |
| 外觀 | 淺色、深色或跟隨系統；介面密度 | M1 |
| 登入 | 修改密碼；目前的登入工作階段 | M4 |

- **安全**：API key 儲存後只顯示末四碼，不能再次查看完整內容，只能更換。
- **API**：`GET/PUT /api/settings/:section`、`POST /api/providers/:id/test`、`POST /api/cookies`、`GET /api/system`、`POST /api/tools/yt-dlp/update`、`GET/POST/DELETE /api/mcp-tokens`

## 13. 登入

- **目的**：保護部署在 VPS 或區網上的實例。
- **里程碑**：M4
- **版面**：
  - Opal 背景中央放一張 Sheet 卡片，內容是 episteme 字標、密碼欄位、「登入」按鈕。
  - 背景是一條淡化的時間帶，畫的是固定的示意資料。登入前不能露出任何實際內容，所以不使用真實影片的資料。登入頁只有這一個裝飾元素。
- **錯誤**：「密碼不正確。」連續失敗 5 次後鎖定 1 分鐘，並顯示剩餘時間。
- **API**：`POST /api/auth/login`、`POST /api/auth/logout`
